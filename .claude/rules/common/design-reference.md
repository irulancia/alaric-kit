# Design System — full reference

Loads when a .svelte, .css or .html file is read or edited. The rules that apply everywhere, and the list of every class `app.css` ships, are in `design.md`. This file has two parts: **using** the design system, and **building** something it doesn't have yet.

Source of truth for tokens: `src/app.css` (`:root`), generated by the configurator — never edited by hand.

# Part 1 — Using the design system

## Colors
- Background: `--bg-primary` (page), `--bg-card` (a raised surface: cards, sidebar, navbar), `--bg-surface`, `--bg-hover`
- Text: `--text-primary`, `--text-secondary`, `--text-label` — all pass 4.5:1 on every surface. Never pure black (`#000`).
- Border: `--border`, `--border-subtle`, `--border-control` (3:1, a control's outline).
- **The primary color has three roles, not one:**
  - `--accent`: the exact color chosen. Backgrounds only (buttons, `.pagination-item.is-active`), with `--on-accent` text.
  - `--accent-ui`: outlines, underlines, switches, progress, focus ring (3:1).
  - `--accent-text`: links, navigation, labels, badges on light surfaces (4.5:1).
  - **Never use `--accent` as text or an outline** — on a light primary (yellow, beige) it is illegible on white.
  - `--accent-hover`: a button's hover fill. `--accent-text-hover`: a link's hover. **Never use `--accent-hover` as text** (on a light primary it drops to ~2.3:1).
  - `--accent-bg` / `--accent-bg-subtle`: light tints for a selected or highlighted area.
- State: `--success`, `--error`, `--warning`, `--info`, each with `-strong` (text on their tints, 4.5:1+), `-bg` and `-border`. They don't follow the brand: red is an error whatever the primary. When the primary resembles a state colour, the difference comes from **the icon and the words**, never colour alone.
- Field messages have `has-error` / `has-success` states (a colored line + label + message, with an icon), on `.field-group` or directly on `.field`.
- Text on colored backgrounds: `--on-accent`, `--on-secondary`, `--on-error` — never pick white or black by hand.
- Also: `--focus-ring`, `--disabled-bg`, `--disabled-text`, `--overlay` (the backdrop behind modals), `--shadow-color`.
- For `rgba()` with a variable opacity on the primary: `--accent-rgb` (`rgba(var(--accent-rgb), 0.2)`).

## Typography
- **Two font tokens**: `--font-display` (H1–H3, `--text-display`) and `--font` (everything else). They may be the same font.
- Sizes only from the scale: `--text-display`, `--text-h1`, `--text-h2`, `--text-h3`, `--text-body`, `--text-small`, `--text-xs`. The whole scale follows the project's density; headings shrink by themselves on small screens — don't redefine mobile sizes locally.
- **The text you read is `--text-body`** (paragraphs, card descriptions, inputs). **A control's text is `--text-ui`**: default buttons, toggle, segmented, switch / check / radio labels, tabs, navbar links, sidebar and menu items. `.btn-lg` keeps the body size; `.btn-sm` is `--text-small`. Inputs stay at the body size (under 16px, iOS zooms in).
- **Table cells are `--text-small`**; the column header the same size, semibold, `--text-secondary`.
- H4–H6, if they appear, are `--text-body` + `--weight-semibold` — not new sizes.
- Weights: `--weight-regular` / `-medium` / `-semibold` / `-bold`. A quiet heading is `--text-body` + `--weight-medium`, not bold.
- Line height: `--leading-tight` on headings, `--leading-loose` on text.
- `--text-display`: the one big title of a landing page, not a page title.
- **Overline / eyebrow** (`.text-overline`): small, uppercase, semibold, `--text-label`. For section labels, group titles and above a heading. It works on any element, a heading included. A class on a heading always wins over the heading's own size.
- **Wordmark** (`.navbar-brand`): uppercase, `--text-secondary` — reads as a mark, not a link.
- **Metadata** (`.card-meta`: who / when, the person's name a `.link`): `--text-xs` in `--text-label`, led by a small icon. Order on a card: **badge, title, metadata, description, action.** A description is `.text-muted`, not `.card-meta`.

## Icons
- The icons are in `app.css`, in the project's style (outline, filled or duotone): `<span class="icon icon-house" aria-hidden="true"></span>`, painted in `currentColor`. The names are the `.icon-*` rules at the end of the file. Never drawn by hand, copied from elsewhere, or built into an Icon component.
- Sizes: `.icon-sm` (in `.btn-sm`, badges, tags), default, `.icon-lg` (in `.btn-lg`, empty states). They follow density.
- **Base roles use the circled icons**: close `x-circle`, add `plus-circle`, confirm `check-circle`, next `caret-circle-*` / `arrow-circle-*`, menu `dots-three-circle`. Edit is `note-pencil`.
- Alerts and toasts: info `info`, success `check-circle`, warning `warning`, error `x-circle` — an icon from the set, not a character drawn in CSS.
- Icons support a label, they don't replace it; an icon-only button has an `aria-label` and a tooltip.
- If the project chose "Affect buttons and pills", `<body>` also has `controls-outline` or `controls-duotone`: primary, secondary, destructive buttons and badges then follow the icon style (tertiary and ghost don't). The `app.css` header says so.

## Which component — DON'T reimplement what exists
- **Buttons**: `.btn` + `.btn-primary` / `.btn-secondary` / `.btn-tertiary` / `.btn-destructive` / `.btn-ghost`; sizes `.btn-sm`, default, `.btn-lg`. Small for dense places (tables, toolbars, cards), default for most actions, large rarely — a call to action, never inside a card. One primary per view. A button never wraps.
- **`.btn-ghost`**: no fill until hover, grey icon; `.is-danger` turns red on hover. For icon-only buttons in table rows and toolbars — a tertiary there reads as a column of coloured blotches.
- **Which control for which job**: one of 2–6 options → `.segmented`; a setting on / off → `.switch`; a tool that stays pressed (Bold, Mute) → `.toggle`; a few related but separate actions (Previous / Today / Next) → `.btn-group`; several ways to do one thing (Export as CSV / PDF) → ONE button with a menu. **Inside a button group every button carries the same kind of content** — all text, all icon + text, or all icon only (only for icons everyone knows, each with a tooltip).
- **Segmented control** (`.segmented`): ONE choice among 2–6 short options — a view, a mode. Not navigation (`.tabs`), not actions (`.btn-group`). Buttons with `aria-pressed` in a `role="group"` with an `aria-label`; the app only sets `aria-pressed`, the indicator slides by itself. Options are equal width and never wrap: more than 6, or long labels → a select. `.is-block` = full width.
- **Form row** (`.form-row` > `.form-row-head` + the control): the label ABOVE a control that isn't a text field — segmented, slider, colour, a group of switches. The head may hold a value at the right (`.form-row-value`) or an "i". Text inputs use the floated-label `.field`.
- **Off, with its reason — not hidden** (`.reason`): a control that doesn't apply now is disabled and says why after its label ("Total in the hole — donut only"). Hide a control only when it belongs to another path entirely.
- **Slider** (`.range`): its value shown in the form row's head, never only by the thumb. Discrete values (2, 3, 4…) are a segmented control, not a slider.
- **Colour picker** (`.color-pick`): the native colour input as a swatch, the hex beside it.
- **The "i"** (`.info-tip` + a `.tooltip` inside, `aria-describedby`): explains a behaviour or consequence; the LABEL says what a control is — no standing help paragraphs. The app adds Esc to dismiss.
- **Tooltip on any element** (`.has-tooltip` around it + a `.tooltip` after it; `.tooltip-end` for the last button of a row): opens on hover and on keyboard focus, Esc closes it. Every icon-only button has one. It repeats the label, so it is `aria-hidden`.
- **Code block** (`pre` inside `.ds-root`, or `.code-block`): scrolls sideways instead of wrapping.
- **A real dialog** (`<dialog class="dialog">` + `showModal()`): focus kept inside, Esc closes; buttons in a `<form method="dialog">` close it with no script. Parts: `.dialog-icon` (optional), the title, `.dialog-description`, `.dialog-close` (a ghost icon button with its tooltip, in the header's corner). Sizes: `.dialog-sm` (a confirmation), default, `.dialog-lg` (a form, reading). With the × there, the footer doesn't repeat "Close" — it carries the action that moves on.
- **A real drawer** (`<dialog class="drawer">` + `showModal()`): the same, full height at the end edge.
- **Toasts** go in one `.toast-region` (`popover="manual"`, so it sits above an open dialog), stacked at the bottom end.
- **A menu or popover opened from a button** carries the `popover` attribute (Esc and a click outside close it); the app places it under its button, end-aligned. An avatar that opens the account menu is a `button.avatar`.
- **An empty state shows wherever emptiness is normal**, not only after a filter: icon, a title saying what is missing, one sentence, the one action that fills it.
- **Card actions** (`.card-actions`): one row at the card's bottom, all ONE size (never `.btn-lg`), primary first; a quiet way out is a `.btn-ghost`.
- **Card header** (`.card-header`): a card's title and its one action or badge. **Stat** (`.stat`: `.stat-label`, `.stat-value`, `.stat-delta.is-up / .is-down` with an arrow AND words).
- **A list of people**: the person is the row — name (`.list-item-title`, not a link), role and presence on the meta line, extra info as read-only tags on a third line, details from an icon button at the end. Presence is a dot on the avatar (`.avatar-status` + `.presence.is-online` / `.is-away`) AND a word, never a pill at the row's far end, never colour alone. Names are links inside sentences and tables.
- **Accordion**: the question semibold, the answer `--text-secondary`; a chevron, not +/−; an open row tinted `--bg-surface`.
- **Link kinds**: `.link` inside a sentence (underlined). `.link.link-action` standing alone as an action ("View details"): no underline until hover. `.link.link-quiet` a neutral path (a "back"). A link that can't act now: `.link:disabled` / `[aria-disabled="true"]`. People's names (author, owner) are `.link`, in cards and tables alike.
- **Table actions column** (`.table-actions` + `.row-actions`): narrow, right-aligned; the header is `.sr-only`, every button has an `aria-label` naming the row ("Edit Acme Corp").
- **Badges**: `.badge`, `.badge-lg`; `.badge-count` for a number (1–2 digits make a circle). A badge never wraps — if a table gets too narrow, drop a column.
- **Stacks** (`.stack`, `.stack-sm`, `.stack-lg`): children one under another; each works alone (`stack-lg` = `stack stack-lg`).
- **Grids**: `.grid-2` / `.grid-3` / `.grid-4` — six cards make 3 + 3, never 5 + 1, and drop to fewer columns as space shrinks.
- **Sidebar**: neutral text and icons; the active row has `--accent-bg-subtle`, semibold text, an `--accent-text` icon and a short `--accent-ui` bar — the colour in two places, not the whole row. Group headings are overlines.
- **Navbar on a phone**: a `.navbar-toggle` button (`aria-expanded`); the app toggles `.is-open` on the navbar. Without a toggle the links only wrap. **Footer**: `.footer` + `.footer-links` for an app's pages; `.footer-site` for a site.
- **Touch**: Compact density goes under 44px — it is for dense desktop interfaces; a touch-first project uses Normal or Spacious.

## Page layouts
- From `app.css`, after the components: app shell (`.app-shell` + `.app-main`: the sidebar beside main, stacked under 48rem), page header (`.page-header` + `-text` + `-actions`), section header (a title and ONE action), description list (`.dl`).
- **Form sections** (`.form-section` > `.form-section-head` + `.form-section-body`): what a group of settings is for on the left, its controls on the right, stacked on a narrow screen. Related controls in a `.fieldset` with a `legend`; the form ends with one `.form-actions` row (Discard, Save). This is how a settings page is laid out.
- **Landing**: `.text-display`, `.text-lead` (the paragraph that introduces a page or section), `.hero` (overline + display title + lead + `.hero-actions` — where `.btn-lg` belongs), `.section-head`, `.feature` (+ `.feature-icon`, in a `.grid`), `.steps` (only `.is-current` filled), bands `.band` / `.band-alt` / `.band-center`, `.split`.
- **Content width is the project's choice**; `.container` is there for a project that wants a cap. Backgrounds still run edge to edge.

## Forms
- `.field`: a lightly tinted field with a 2px underline; the label sits inside like a placeholder and moves up on focus or once filled. Markup: the input with `placeholder=" "`, then its `label`. For `textarea` the label starts at the top.
- States: error (`has-error`: border, label and a message below, with an icon), disabled, focus (the underline thickens in `--accent-ui`).
- Applies to input, textarea, select and input group (`.input-group` + `.input-addon`). Checkbox, radio and switch have their label beside them, not floated.
- A field that could hold long text is a `<textarea>` (with auto-resize), never an `<input>`.

## Using app.css in the project
- `class="ds-root"` on `<body>` (element typography is scoped to it), plus `controls-outline` / `controls-duotone` if the header comment says so.
- The file isn't edited by hand: change the choices in the configurator and save again. The configurator opens with the choices the project's `src/app.css` was saved with, in any browser; its Reset goes back to them.
- It is read live, not built into the app (SvelteKit: `rules/stack/svelte.md`), so a save shows on the next refresh.
- **Not in `app.css`**: the behaviour of interactive components (opening a dialog, placing a menu, showing a toast) — the project writes its own, with the markup above.
- Don't compute colors by hand and don't set themes per page: the tokens carry the theme.

# Part 2 — Building something the design system doesn't have

## First: ask where it goes
1. **Check it really is missing**: the class list in `design.md` ("What exists") and Part 1. A variant of something that exists (a size, a state, a colour) is not a new component.
2. **Say what is missing, in words, and ask the owner where it belongs** — don't build it yet:
   - **in the design system**: its styles go in `.claude/scripts/configurator/styles/components.css` (a component) or `configurator/styles/layouts.css` (a page layout); the class list in `design.md` updates by itself. Then **stop and ask the owner** to open the configurator and press **Save src/app.css** — Claude can't save it, the project's choices live in the configurator. Continue only once they say it is saved (the new class is in `src/app.css`);
   - **only in this project**: a component (e.g. `src/lib/components/Calendar.svelte`) keeps its styles inside itself (a Svelte `<style>`); a class shared by several pages that isn't a component goes in **`src/project.css`**, imported right after `app.css` (bootstrap creates it). **Never written into `src/app.css`**, which every save from the configurator rewrites whole. Built from the tokens by the rules below.
   - **a value only this project has** (a colour for its charts, an illustration on the home page): a token of its own, defined in `src/project.css` (`:root { --chart-warm: #f4a582; }`) and used only through `var()` — the one place a literal is allowed outside `app.css` (`check-design-tokens.sh` lets the definitions through and still blocks a literal anywhere else). Named by its role (`--chart-warm`, `--illustration-sky`), not by its colour (`--peach`). It gets a dark-mode value next to it if the project has a dark theme. The configurator never checks it, so it is for charts and decoration: a chart mark or an icon needs 3:1 against its background, and text in it is checked by hand for 4.5:1. If more than one project would want it, it belongs in the configurator instead.
3. Never a quiet local version "just to make it work" — that is how a project ends up with two buttons that almost match.
4. **Note it in `memory/backlog.md`** as a design system addition: what it is, why the system lacked it, and where it went (design system or project only). The project's design system is its own copy, so it can grow past the kit it started from; the note keeps what it added, and why, findable.

## The rules any new component follows
- **Tokens only**: colours, sizes, spacing, radius, shadows, z-index all from `app.css`. No literal hex/rgba, px or z-index (`check-design-tokens.sh` blocks the obvious ones). A value that has no token is added through the configurator, not hardcoded once.
- **Colour roles** as in Part 1: `--accent` only as a fill with `--on-accent` text; `--accent-ui` for its outline or indicator; `--accent-text` for its text. State colours carry an icon and words too.
- **Spacing**: only `--space-0` … `--space-12`. Padding only inside something with a visible background or border. **Never a fixed margin on the component** — the parent positions it. `gap` between its children, not a margin on each. Proximity: inside a group half the gap between groups (`--space-2` vs `--space-3`).
- **Radius by role**, never one value for everything:

| Token | For |
|---|---|
| `--radius-control` | buttons, toggles, pagination pages |
| `--radius-field` | input, textarea, select (top corners only — the bottom is an underline) |
| `--radius-chip` | tag, tooltip, `code`, checkbox, focus rings on link/tab |
| `--radius-surface` | card, alert, toast, menu, sidebar, popover, table, list, accordion |
| `--radius-overlay` | dialog |
| `--radius-pill` | badge, progress, switch |

- **Nested in a rounded container (concentric rule):** inner radius = the container's radius minus its padding, e.g. `max(0px, calc(var(--radius-surface) - var(--space-2)))`. A row at a container's edge gets `calc(var(--radius-surface) - 1px)`, so hover and the focus ring follow the curve; a list with row hover gets `overflow: hidden`.
- **Shadows**: `--shadow-sm` (resting), `--shadow-md` (raised: menu, popover), `--shadow-hover` (interactive, dialog); never a black or brand-coloured shadow written by hand; no animated multi-layer shadows on long lists. **Layers**: `--z-dropdown` / `--z-overlay` / `--z-modal` / `--z-toast`.
- **Sizes**: a control's height is `--control-height-sm` / `--control-height` / `--control-height-lg`, a dense row `--row-height`, set with `min-height`; vertical padding stays small (`--space-1` / `--space-2`). Its text is `--text-ui` (a control) or `--text-body` (something you read).
- **States**: hover, focus, active and disabled, each one visible. Disabled uses `--disabled-bg` / `--disabled-text`, and says why (`.reason`) when the reason isn't obvious.
- **Focus**: `outline: 2px solid var(--focus-ring); outline-offset: 2px` — an outline, never a box-shadow. A variant sets its own ring with a local `--ring`, read as `var(--ring, var(--focus-ring))`. Inside a container that clips it (a menu, an accordion), the offset goes inward.
- **Accessibility**: a real element for the job (`button`, `dialog`, `a`), an `aria-label` on anything icon-only plus a tooltip, keyboard use (Tab, Enter, Esc), touch targets of 44px at Normal density.
- **Inline editable field**: a full border (transparent → `--accent-ui` on focus, `--accent-bg-subtle` on hover) if it can hold more than one line; an underline only if it is guaranteed to stay on one line.
- **Motion**: hover / focus `transition: all 0.2s ease`; an overlay's entrance `cubic-bezier(0.22, 1, 0.36, 1)`, 0.25–0.3s; no decorative animation without a purpose. Reduced motion is already handled in `app.css`.
